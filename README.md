# RE/MAX COMPASS 物件ポータル

商業不動産・店舗仲介を専門とする **RE/MAX COMPASS（株式会社ロメッツ）** の事業用不動産ポータルサイト。
**賃貸・売買の両方**に対応し、店舗・オフィス・倉庫・一棟ビル・事業用地を、エリア／賃料・価格／面積／駅徒歩／こだわり条件で検索できます。
対応エリアは**一都三県（東京都・神奈川県・埼玉県・千葉県）**です。

> **重要**
> - 掲載している **物件情報はすべてデモ用のサンプルデータ** です。実在の募集物件ではありません。
> - 公開前に必ず **[公開前チェックリスト](#公開前チェックリスト)** をご確認ください。

以前の1枚もののランディングページは本ポータルに置き換えました（内容は git 履歴に残っています）。

## 技術構成

- **サイト本体は素の HTML / CSS / JavaScript**（ビルド不要・実行時の依存パッケージなし）
- 物件データは `data/properties.js` にグローバル変数として定義（`file://` でも動作します）
- フォント: Google Fonts（Montserrat, Zen Kaku Gothic New）
- `package.json` の依存は **運用ツールとテスト用** です（画像の自動縮小と自動テスト）。サイトの表示には不要です

```bash
npm install          # 運用ツールとテストの準備（初回のみ）
npm run sync         # スプレッドシートを取り込んでサイトに反映
npm run build        # data/properties.csv からサイトのデータを生成
npm run check        # 書き込まずに検証だけ
npm run serve        # http://localhost:8080 でローカル確認
npm test             # 実ブラウザでの自動テスト
```

## 主な機能

### 検索・絞り込み（`properties.html`）

- **取引種別（賃貸／売買）**: 検索画面の先頭で切り替えます。**賃貸と売買は常にどちらか一方だけを表示** し、混在しません。既定は賃貸
- **絞り込み条件**: フリーワード / 物件種別 / 都県 / エリア（市区） / **沿線・駅** / 月額賃料レンジ（賃貸）・販売価格レンジ（売買） / 面積レンジ（坪） / 駅徒歩 / 募集状況 / こだわり条件（居抜き・1階路面・セットアップ 等）
- **沿線・駅は物件データから自動で一覧化**されます。マスタ管理は不要で、物件の「交通」列に書いた路線・駅がそのまま選択肢になります
- **エリアは都県 → 市区の2階層**。都県を選ぶと、エリアのチェックボックスがその都県の市区だけに絞られます。都県のチェックを外すと、その都県で選んでいた市区も自動的に外れます。東京都は数が多いため「23区」「多摩・市部」の小見出しで分けて表示します
- **成約済の物件は検索結果に出ません**（「成約済」を明示的に選んだときのみ表示）。詳細ページは残るため、過去の取扱実績としてURLを共有できます
- **並び替え**: 新着順・面積の広い/狭い順・坪単価の安い順に加え、賃貸は賃料の安い/高い順、売買は価格の安い/高い順と**利回りが高い順**
- **ページング**: 1ページ9件
- 条件は **URLクエリと同期** するため、検索結果をそのまま共有・ブックマークできます（例: `properties.html?type=shop&area=千代田区&feature=居抜き`、売買は `properties.html?deal=sale&type=building`、都県は `properties.html?pref=kanagawa,chiba`）
- 取引種別を切り替えると、金額の絞り込み（賃料／価格）と並び替えはリセットされます（単位が違うため持ち越しません）
- 選択中の条件はチップで表示し、クリックで個別解除
- 各チェックボックスに該当件数を表示、絞り込み結果は入力と同時に更新
- 1024px以下では絞り込みパネルがドロワーに切り替わります

### 物件詳細（`property.html?id=...`）

この物件についての説明、契約までの流れ、物件個別のお問い合わせフォーム、類似物件のレコメンド（同じ取引種別の中から選びます）。ページタイトルと meta description は物件情報から動的に生成します。

物件概要テーブルは取引種別で内容が変わります。

| | 賃貸 | 売買 |
|---|---|---|
| 金額 | 月額賃料・共益費・敷金・礼金 | 販売価格・表面利回り・権利形態 |
| 坪単価 | 月額賃料 ÷ 坪数 | 販売価格 ÷ 坪数 |
| 時期 | 入居可能時期 | 引渡し時期 |
| 契約までの流れ | 詳細資料 → 条件交渉・申込 → 重要事項説明・契約 | 資料のご開示 → 買付・条件交渉 → 売買契約・決済 |

### 宅建業法・表示規約への対応

物件情報の掲載は、**宅地建物取引業法**と**不動産の表示に関する公正競争規約（表示規約）**に沿った表示を自動で行います。

| 要求事項 | 対応 |
|---|---|
| 取引態様の明示（法34条） | 全物件に「取引態様：仲介」を表示 |
| 報酬額（法46条） | 物件概要・契約の流れ・全ページのフッターに、法に定める報酬額である旨と金額を明示 |
| 取引条件の有効期限（表示規約） | **情報更新日から14日後を自動算出**して表示。入力不要 |
| 契約期間（表示規約・賃貸） | CSVの「契約期間」列。空欄だと警告が出ます |
| 用途地域・建ぺい率・容積率（表示規約・売買） | CSVの各列。売買で用途地域が空だと警告 |
| 私道負担（表示規約・土地） | CSVの「私道負担」列。土地の売買で空だと警告 |
| 建築確認番号（法33条・未完成物件） | CSVの「建築確認番号」列。入力があれば表示 |
| 消費税の扱い | 金額に「（税別）」を付記。フッターにも共通表示 |
| 写真の扱い（表示規約 規則9条） | 実写真は「当該物件を撮影したもの」、未掲載時は「イメージイラストで当該物件とは異なる」と明記 |
| 情報提供元・免許番号 | 物件概要と全ページのフッターに表示 |
| 誇大広告の禁止（法32条） | 表示規約の特定用語（「完全」「絶対」「最高級」等）が入っていないかを`npm test`で自動チェック |
| おとり広告の禁止 | 成約済は検索結果から自動的に消え、詳細ページには成約済と明示 |

**運用で気をつけていただきたいのは2点だけです。**

1. **賃貸は「契約期間」を入力する**（普通借家か定期借家かも書いてください）
2. **売買は「用途地域」を、土地はさらに「私道負担」を入力する**

どちらも空欄だと変換時に警告が出るので、入れ忘れに気づけます。

### お問い合わせ

物件ページとお問い合わせページの2箇所にフォームがあります。

- 送信先は `SITE_CONFIG.form` で設定します。既定は **FormSubmit**（アカウント登録不要）で、`eiichiro.mukai@remax-agt.net` に届きます
- **初回だけ、FormSubmitから届く確認メールのリンクを開いて承認**してください。承認するまでメールは届きません
- Formspree など他のサービスに変えたい場合は `endpoint` を差し替えるだけです
- **プライバシーポリシーへの同意チェックが必須**です。同意しないと送信できません。同意文は「物件情報のご案内（メール・郵送等）を受け取ることに同意します」となっており、**メールマガジン・DMの送付についても同意を取得**しています
- 返信の目安は**2営業日以内**と表示しています
- 資料の郵送に使えるよう、**ご住所欄**（任意）があります
- 送信に失敗した場合は、入力内容を保ったまま **同じ内容でメールを作成できるリンク**とお電話の案内を出します（機会損失を防ぐため）
- 物件ページからの送信には、物件番号・物件名・物件URL・金額が自動で添付されます

### アクセス解析

`SITE_CONFIG.analyticsId` に GA4 の測定ID（`G-XXXXXXXXXX`）を入れると有効になります。**空のあいだは Google のスクリプトを一切読み込みません。**

記録するイベント:

| イベント | 内容 |
|---|---|
| `search` | 検索条件と結果件数（どのエリア・駅・種別が探されているか） |
| `view_property` | 物件ページの閲覧（物件番号・種別・エリア・金額） |
| `add_favorite` / `remove_favorite` | お気に入りの登録・解除 |
| `inquiry_submit` | お問い合わせの送信（どの物件からか） |
| `inquiry_error` | 送信の失敗（フォームの不具合に気づくため） |

IPアドレスは匿名化しています。

### SEO

- **sitemap.xml / robots.txt は自動生成**されます（`node tools/csv-to-properties.js` 実行時）。物件ページ・都県別検索ページを含め、現在63URL
- 各ページに **canonical・OGP・Twitterカード**を出力。物件ページはタイトル・説明・画像を物件ごとに差し替えます
- 物件ページに **構造化データ（JSON-LD）** を出力。`RealEstateListing` として価格・面積・所在地・写真を、`BreadcrumbList` としてパンくずを渡します
- トップページには `RealEstateAgent`（会社情報）と `WebSite`（サイト内検索）を出力

### 物件写真（1物件10枚まで）

**写真は `images/properties/` にファイルを置くだけで掲載されます。スプレッドシートを触る必要はありません。**

```
images/properties/
  CMP-1025-01_外観.png      ← 1枚目。一覧カードとメイン画像に使われます
  CMP-1025-02_店内.png      ← 「_」のあとはキャプション（省略可）
  CMP-1025-03_厨房.png
```

ファイル名のつけかたは `<物件番号>-<番号>[_キャプション].<拡張子>` です。

| | |
|---|---|
| 枚数 | 1物件あたり**10枚まで**（11枚目以降は警告を出して掲載しません） |
| 並び順 | ファイル名の番号順。**01がメイン画像** |
| キャプション | `_` のあとの文字。詳細ページの写真の下に出ます。省略可 |
| 拡張子 | jpg / jpeg / png / webp / avif / gif |
| サイズ | 長辺1600px・1.5MB以下推奨（超えると警告が出ます） |

置いたあと `node tools/csv-to-properties.js` を実行すると反映されます（CSVの反映と同じコマンドなので、手順は増えません）。消したいときはファイルを削除して同じコマンドを実行します。

写真が2枚以上ある物件の詳細ページには、サムネイル・前後の矢印・枚数カウンタが自動で付きます。

**写真が1枚もない物件**は、物件種別とIDから決定的に生成する SVG プレースホルダを表示します（`js/portal.js` の `placeholderImage()`）。RE/MAX公式カラーの4種のパレットで、店舗・オフィス・倉庫・一棟ビル・事業用地を描き分けます。詳細ページには「画像は物件種別に基づくイメージ」である旨を明記します。

次のような入力ミスは変換時に警告が出ます（書き込みは止まりません）。

- ファイル名の形式が違う → 読み込まずに警告
- 対応する物件番号がない → 読み込まずに警告
- 11枚以上ある → 先頭10枚だけ掲載して警告
- 1.5MBを超えている → 掲載はするが警告

### 地図表示について

**所在地に「番地・号」まで入っている物件だけ**、詳細ページにGoogleマップが表示されます。丁目までしか入っていない住所は場所を特定できないため、地図を出しません（別の場所を指してしまうのを防ぐためです）。

| 所在地の書きかた | 地図 |
|---|:--:|
| `東京都千代田区神田三崎町三丁目4番9号` | ✅ |
| `東京都立川市曙町2-39-3` | ✅ |
| `東京都千代田区神田三崎町三丁目` | ❌（丁目まで） |

つまり**運用上の操作は「所在地を番地まで書く」だけ**です。設定は不要です。

設定は `data/properties.js` 冒頭の `MAP_CONFIG` にあります。

```js
var MAP_CONFIG = {
  enabled: true,   // false にすると地図を一切出しません
  apiKey: '',      // Google Maps Embed API のキー（任意）
  zoom: 17
};
```

`apiKey` が空のときは、キーのいらない埋め込みURL（`maps.google.com/maps?...&output=embed`）を使います。**設定ゼロで動きますが、これはGoogleの公式なAPIではないため、仕様変更で止まる可能性があります。**

長く運用するなら、公式の **Google Maps Embed API** に切り替えることをおすすめします（Embed APIは無料枠内で使えます）。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「Maps Embed API」を有効にする
3. APIキーを発行し、**HTTPリファラー制限**で自社ドメインだけに絞る
4. そのキーを `MAP_CONFIG.apiKey` に貼る

キーを入れると自動で公式の埋め込みURLに切り替わります。コードの変更は不要です。

## デザインシステム

- **カラー**: RE/MAX公式パレットを `css/style.css` の `:root` にCSS変数として厳密値で定義（Red `#FF1200` / Blue `#0043FF` / Cream `#F7F5EE` / Black / White / Dark Red `#650000` / Dark Blue `#000B35` / Bridge Red・Blue / Sky Blue / Dark Charcoal Gray）。背景は白・クリーム・濃紺中心、赤をCTA・賃料表示のアクセントとして使用
- **フォント**: Montserrat（見出し・数字）+ Zen Kaku Gothic New（日本語本文）
- **レイアウト**: 余白とヘアラインで区切る編集的なレイアウト、左寄せ見出し、ダッシュ＋テキストの控えめなCTA（`.link-cta`）
- **コントラスト対応**: 赤地に白文字は基準（4.5:1）未達のため、赤ボタンは黒文字（5.3:1）、ホバー時は濃赤地に白文字へ切り替え
- **アクセシビリティ**: スキップリンク、`aria-live` による検索結果件数の通知、フォーカスリング、`prefers-reduced-motion` 対応、フォームのリアルタイムバリデーションとエラーの `aria-invalid` 連動

## 物件データの追加・編集（スプレッドシート運用）

**日常のメンテナンスはGoogleスプレッドシートで行います。** JavaScriptもCSVファイルも直接編集する必要はありません。

### CSVはどこにある？何に入力する？

| | |
|---|---|
| **入力する場所** | **Googleスプレッドシート**（複数人で同時編集できます） |
| ファイルの置き場所 | `data/properties.csv`（リポジトリ内） |
| 役割 | スプレッドシートの内容を写したもの。**スクリプトが書き換えるので、手で編集しないでください** |
| 形式 | UTF-8（BOM付き）・カンマ区切り・26列 |

つまり **原本はGoogleスプレッドシート、`data/properties.csv` はその写し**です。人が入力するのはスプレッドシートだけです。

### 初回セットアップ（1回だけ）

```bash
node tools/properties-to-csv.js        # 現在の物件データを data/properties.csv に書き出し
```

1. Googleスプレッドシートで新規シートを作る
2. [ファイル] → [インポート] → `data/properties.csv` をアップロード
   （区切り文字は**カンマ**、「テキストを数値に変換」は**オフ**推奨）
3. 右上の［共有］で、必要な人を**編集者**として追加する
4. 同じ［共有］の「一般的なアクセス」を **「リンクを知っている全員」→「閲覧者」** にする
5. ブラウザのアドレスバーのURLをコピーして、`tools/sheet-url.txt` に貼り付けて保存する

これで準備完了です。以後、**チームの誰でもスプレッドシートを編集できます。**

> **共有設定についての注意**
> 手順4は、URLを知っている人なら誰でもシートを**読める**状態にします（編集はできません）。
> 掲載予定の物件情報はどのみち公開サイトに載るものなので通常は問題ありませんが、
> **公開前の物件や社内メモを同じシートに書かないでください。**
> 分けたい場合は「公開用シート」を別タブにして、そのタブのURL（`gid=` 付き）を設定してください。

### 更新のたびに行うこと

1. スプレッドシートで物件を追加・修正する（**ここは誰がやってもOK**）
2. 写真を追加・削除する場合は `images/properties/` のファイルを入れ替える（→「物件写真」の項）
3. 取り込みコマンドを実行する

```bash
node tools/fetch-sheet.js           # シートを取得して反映まで行う
node tools/fetch-sheet.js --check   # 取得して検証するだけ（何も書き換えない）
```

4. `git add -A && git commit && git push` で公開

**入力に問題があれば、CSVもサイトのデータも一切書き換えません。** 何行目の何が悪いかを日本語で表示して止まるので、シートを直して再実行してください。

### 手を動かさずに反映する（自動同期）

`.github/workflows/sync-sheet.yml` を用意してあります。有効にすると **30分おきにスプレッドシートを見に行き、変更があれば自動でサイトに反映**します。コマンドを実行する人すら不要になります。

準備は3つだけです。

1. `tools/sheet-url.txt` にURLを書く（上の初回セットアップと同じ）
2. スプレッドシートの共有を「リンクを知っている全員」→「閲覧者」にする
3. GitHubの **Settings → Actions → General → Workflow permissions** を
   「**Read and write permissions**」にする

これで、スプレッドシートを直すだけでサイトが更新されます。
入力ミスがあった場合は**サイトを変更せず**、Actionsタブに失敗として残り、どの行の何が悪いかがログに日本語で出ます。

自動反映を止めたいときは、ワークフロー内の `schedule:` の3行をコメントアウトしてください（Actionsタブからの手動実行だけ残ります）。

> **写真だけは自動同期の対象外です。** 画像ファイルはリポジトリに置く必要があるため、
> `images/properties/` への追加・削除は git での操作になります。

（Microsoft 365 の公開リンク、自社サーバー上のCSVなど）。処理と検証は同じです。

### 自動でチェックされること

エラー（書き込みを中止）は、必須項目の欠落、物件番号の重複、種別・募集状況・エリア・こだわり条件がマスタにない、数値項目に数値以外、日付の形式誤り、交通の形式誤り。
警告（書き込みは実行）は、賃料が1万円未満または5,000万円超、販売価格が100万円未満、表面利回りが30%超、面積が1,000坪超、築年が範囲外、取引種別と合わない金額列に入力がある、交通や物件説明が空。**桁の入力ミスはここで気づけます。**
都県とエリアの食い違い（例: 都県「埼玉県」・エリア「横浜市」）はエラーとして止まります。

こだわり条件や物件種別の選択肢を増やす場合は、`data/properties.js` 冒頭の `FEATURES` / `PROPERTY_TYPES` に追加してください（この部分は生成対象外なので手で編集します）。検索画面のチェックボックスは、該当件数が1件以上ある項目のみ自動表示されます。

### 対応エリアを増やす

エリアのマスタは `data/properties.js` 冒頭の `AREA_MASTER` です。都県ごとに市区名の配列を持ち、**市区名から都県が自動で決まる**ようになっています（同じ市区名を複数の都県に入れないでください）。

```js
var AREA_MASTER = {
  /* 数が多い都県は { 小見出し: [市区名…] } と書ける */
  tokyo: {
    '23区':      ['千代田区', '中央区', /* …23区… */],
    '多摩・市部': ['八王子市', '立川市', /* …26市… */]
  },
  /* 少ない都県はそのまま配列でよい */
  kanagawa: ['横浜市', '川崎市', /* … */],
  saitama:  ['さいたま市', '川口市', /* … */],
  chiba:    ['千葉市', '船橋市', /* … */]
};
```

現在の収録は **計83**です。

| 都県 | 収録 |
|---|---|
| 東京都 | 23区すべて＋26市すべて（49） |
| 神奈川県 | 主要12市 |
| 埼玉県 | 主要11市 |
| 千葉県 | 主要11市 |

市を追加したいときはその都県の配列に足すだけで、検索の絞り込み・トップの「エリアから探す」・ヒーロー検索の選択肢・CSVの入力チェックにすべて反映されます。政令市を区単位で扱いたい場合（`横浜市西区` など）も、同じ配列に区名を並べれば動きます。小見出しは絞り込みとトップページの表示にだけ効くもので、絞り込みの単位はあくまで市区です。

一都三県の外へ広げる場合は `PREFECTURES` に都道府県を足し、`AREA_MASTER` に同じキーで配列（または小見出し付きのオブジェクト）を追加してください。

### 直接編集する場合

`data/properties.js` の `PROPERTIES` 配列は `PROPERTIES:BEGIN` / `PROPERTIES:END` のマーカーで囲まれた生成領域です。スプレッドシート運用中にここを手で編集すると、次回の変換で上書きされます。手編集に切り替える場合は変換スクリプトを使わないでください。配列の書式は次のとおりです。`areaSqm`（m²換算）と `tsuboUnitPrice`（坪単価）はファイル末尾で自動計算されるため、記述不要です。

```js
{
  id: 'CMP-1025',                 // 物件番号（URLのキーになります）
  title: '物件名',
  deal: 'rent',                   // rent（賃貸）| sale（売買）
  type: 'shop',                   // shop | office | warehouse | building | land
  status: 'available',            // available（募集中）| negotiating（商談中）| closed（成約済）
  ward: '渋谷区',                  // AREA_MASTER にある市区名（都県は自動で決まります）
  address: '東京都渋谷区〇〇一丁目',
  access: [{ line: 'JR山手線', station: '渋谷', walk: 5 }],
  rent: 500000,                   // 月額賃料（円）0 で「応相談」表示。deal:'sale' では 0
  managementFee: 40000,           // 共益費（円／月）
  deposit: 10,                    // 敷金・保証金（ヶ月）
  keyMoney: 0,                    // 礼金（ヶ月）
  // ↓ deal: 'sale' のときだけ持たせます
  // price: 980000000,            // 販売価格（円）
  // yieldRate: 4.2,              // 表面利回り（%）0 なら非表示
  // tenure: '所有権',             // 権利形態
  areaTsubo: 25.0,
  floor: '1F',
  floorsTotal: 6,
  builtYear: 2005,
  structure: 'RC造',
  features: ['1階路面', '飲食可'],  // FEATURES 配列の値
  usage: ['飲食店', '物販'],
  availableFrom: '即入居可',       // 売買では引渡し時期として表示
  updatedAt: '2026-08-01',        // 新着バッジの自動判定と新着順の並び替えに使用
  description: '物件の説明文。'
}
```

エリアやこだわり条件の選択肢を増やす場合は、同ファイル冒頭の `AREAS` / `FEATURES` / `PROPERTY_TYPES` に追加してください（検索画面のチェックボックスは、該当件数が1件以上ある項目のみ自動表示されます）。取引種別の選択肢は `DEAL_TYPES` ですが、賃貸／売買の2つを前提に画面を作っているため、増やす場合は `js/portal.js` の `DEAL_CONFIG` と詳細ページの分岐も合わせて調整が必要です。

### 募集状況の運用

物件データが持つ `status` は **募集中 / 商談中 / 成約済** の3つです。「新着」はデータ側で持たず、`updatedAt` から自動判定します（`js/portal.js` の `NEW_DAYS`、既定14日）。掲載日から14日以内なら新着バッジが付き、期間を過ぎると自動的に「募集中」に変わるため、外し忘れは起きません。商談中・成約済の物件には新着バッジは付きません。

成約したら `status: 'closed'` に変更します。検索結果・トップページ・種別/エリアの件数・類似物件から自動的に除外され、詳細ページだけが残ります（成約済の告知と「同じ条件の物件を探す」導線に切り替わり、問い合わせフォームは非表示になります）。データごと削除してしまっても表示は壊れませんが、実績として残す場合は `closed` を使ってください。

### 日付の扱い（サンプルデータ）

サンプルデータでは `updatedAt` 未設定の物件に、掲載順で5日ずつ古い日付を自動割り当てしています。日付ベースで新着を判定するため、**サンプルのまま時間が経つと新着バッジは自然に消えます**。実データでは各物件に必ず `updatedAt` を設定してください。
