# microCMS 導入手順（初回だけ・管理担当者向け）

物件情報の入力を、Googleスプレッドシートから **microCMS の管理画面** に移すための手順です。
**1回やれば終わりです。** 所要時間はおおむね1〜2時間、うち大半は次の「② APIスキーマを作る」です。

日々の運用手順は [MANUAL.md](../MANUAL.md) をご覧ください。

---

## 全体の流れ

1. microCMS のアカウントとサービスを作る
2. **APIスキーマ（入力フォーム）を作る** ← ここが本番
3. GitHub 側の設定をする（サービス名とAPIキー）
4. 反映のタイミングを知る（追加の設定は不要です）
5. 既存53件のデータを移す
6. スプレッドシート運用を止める

---

## ① microCMS のアカウントとサービスを作る

1. https://microcms.io/ で登録する
2. **サービス**を作る。サービスIDは後で使うので控えてください
   （管理画面のURL `https://＜サービスID＞.microcms.io/` の部分です）
3. **API** を作る。作りかたは「**自分で作成する**」を選ぶ
   - API名: 何でも構いません（例: 物件）
   - **エンドポイント: `properties`** ← これは必ずこの値にしてください
   - 型: **リスト形式**

> **料金について**
> 無料プランには、メンバー数・API数・転送量の上限があります。
> 3名程度なら無料枠で足りる見込みですが、**上限は変更されることがあるため、
> 契約前に必ず公式の料金ページで現在の条件をご確認ください。**

## ② APIスキーマを作る

### いちばん速い方法：定義ファイルを読み込ませる

30個以上のフィールドを手で入れる必要はありません。**定義ファイルを用意してあります。**

1. **[docs/microcms-schema.json](microcms-schema.json)** をダウンロードする
   （GitHubの画面右上の「Download raw file」ボタン）
2. 「APIスキーマを定義」の画面で、上部の
   **「ファイルインポートする場合は<u>こちら</u>から」** を押す
3. ダウンロードしたファイルを選ぶ

**フィールド32個・エリア83件・こだわり条件12件が一度に入ります。**

> **読み込みでエラーが出た場合**は、繰り返しフィールド（交通・写真）を除いた
> **[docs/microcms-schema-basic.json](microcms-schema-basic.json)** を試してください。
> 30項目が入るので、残りは交通と写真の2つを手で追加するだけになります。
> それも通らない場合は、下の表を見ながら手で追加してください。
>
> 書式は microCMS が実際に書き出したファイルに合わせています。
> テキスト項目はキー構成まで一致を確認済みですが、数値・日時・繰り返しは
> 書き出しの実物を確認できていません。エラーが出た場合はお知らせください。

このファイルは `data/properties.js` のマスタから自動生成しています。
エリアやこだわり条件を増やしたときは、次のコマンドで作り直してください。

```bash
node tools/make-cms-schema.js
```

### 手で作る場合（または読み込んだ内容の確認用）

管理画面の **API設定 → スキーマ** で、下の表のとおりにフィールドを追加します。

**「フィールドID」は1文字でも違うと取り込めません。** 表示名は自由に変えて構いません。

### 基本

| フィールドID | 表示名 | 種類 | 必須 | 設定 |
|---|---|---|---|---|
| `propertyId` | 物件番号 | テキストフィールド | ✓ | |
| `title` | 物件名 | テキストフィールド | ✓ | |
| `deal` | 取引種別 | セレクトフィールド | ✓ | 選択肢: `賃貸` `売買`（複数選択オフ） |
| `type` | 物件種別 | セレクトフィールド | ✓ | 選択肢: `店舗` `オフィス` `倉庫・工場` `一棟ビル` `事業用地` |
| `status` | 募集状況 | セレクトフィールド | | 選択肢: `募集中` `商談中` `成約済` |
| `ward` | エリア（市区） | セレクトフィールド | ✓ | 選択肢は下の「エリアの選択肢」を貼り付け |
| `address` | 所在地 | テキストフィールド | | 説明に「番地・号まで書くと地図が出ます」と入れておくと親切です |

> **「都県」は作りません。** エリア（市区）から自動で決まります。

### 交通（繰り返しフィールド）

`access` という **繰り返しフィールド** を作り、その中に **カスタムフィールド** を1つ用意します。

| カスタムフィールド内 | 表示名 | 種類 |
|---|---|---|
| `line` | 路線 | テキストフィールド |
| `station` | 駅 | テキストフィールド |
| `walk` | 徒歩（分） | 数値 |

> これで `JR中央・総武線|水道橋|3` のような記号の入力が不要になります。

### 賃貸のとき使う項目

| フィールドID | 表示名 | 種類 |
|---|---|---|
| `rent` | 月額賃料（円） | 数値 |
| `managementFee` | 共益費（円） | 数値 |
| `deposit` | 敷金（ヶ月） | 数値 |
| `keyMoney` | 礼金（ヶ月） | 数値 |
| `contractTerm` | 契約期間 | テキストフィールド |

### 売買のとき使う項目

| フィールドID | 表示名 | 種類 |
|---|---|---|
| `price` | 販売価格（円） | 数値 |
| `yieldRate` | 表面利回り（%） | 数値 |
| `tenure` | 権利形態 | テキストフィールド |
| `zoning` | 用途地域 | テキストフィールド |
| `buildingCoverage` | 建ぺい率（%） | 数値 |
| `floorAreaRatio` | 容積率（%） | 数値 |
| `privateRoad` | 私道負担 | テキストフィールド |
| `buildingPermit` | 建築確認番号 | テキストフィールド |

### 物件の詳細

| フィールドID | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `areaTsubo` | 面積（坪） | 数値 | ✓ |
| `floor` | 階数 | テキストフィールド | |
| `floorsTotal` | 建物階数 | 数値 | |
| `built` | 築年月 | テキストフィールド | |
| `structure` | 構造 | テキストフィールド | |
| `features` | こだわり条件 | セレクトフィールド（**複数選択オン**） | |
| `usage` | 用途 | セレクトフィールド（**複数選択オン**） | |
| `availableFrom` | 入居可能時期・引渡し時期 | テキストフィールド | |
| `description` | 物件説明 | テキストエリア | |

`built` の説明欄には「**`2015-04` のように年-月で入力**」と書いておいてください。

### 写真（繰り返しフィールド）

`photos` という **繰り返しフィールド** を作り、その中に **カスタムフィールド** を1つ用意します。

| カスタムフィールド内 | 表示名 | 種類 |
|---|---|---|
| `image` | 写真 | 画像 |
| `caption` | キャプション | テキストフィールド |

**1件目がメイン画像**になります。**10枚まで**（11枚目以降は掲載されず警告が出ます）。

### 情報更新日（通常は作らなくて構いません）

**何も作らなければ、microCMS の更新日時が自動で使われます。**
「軽微な修正で新着扱いにしたくない」など、日付を自分で決めたい場合だけ、
`infoUpdatedAt`（日時）を追加してください。入力があるとそちらが優先されます。

## ③ GitHub 側の設定

### サービス名を書く

`tools/cms-config.json` の `serviceDomain` に、①で控えたサービスIDを書きます。
**管理画面のURLをそのまま貼っても動きます。**

```json
{
  "serviceDomain": "your-service-id",
  "endpoint": "properties"
}
```

### APIキーを登録する

1. microCMS の **サービス設定 → APIキー** で、**GET権限だけ**のキーを作る
2. GitHub の **Settings → Secrets and variables → Actions → New repository secret**
   - 名前: `MICROCMS_API_KEY`
   - 値: 手順1のキー

> **APIキーはGETだけにしてください。** 更新・削除の権限は不要です。
> 万一漏れても、書き換えられる心配がなくなります。

### 書き込み権限を有効にする

**Settings → Actions → General → Workflow permissions** を
「**Read and write permissions**」にします（自動反映がコミットするために必要です）。

## ④ 反映のタイミングについて

**追加の設定は不要です。** ③まで終わっていれば、次のように反映されます。

| | タイミング |
|---|---|
| 自動 | **15分おき**。「公開」を押してから最大15分でサイトに出ます |
| 手動 | Actions タブ →「物件情報を反映（microCMS）」→ **Run workflow** で即時 |

急ぎの更新は手動実行で対応してください。1〜2分で反映されます。

### 「公開」と同時に反映できないのはなぜか

microCMS の Webhook（カスタム通知）は、**`X-` で始まるヘッダーしか送れません**。
GitHub の API は `Authorization: Bearer ...` を要求するため、
**microCMS から GitHub を直接呼び出すことはできません。**

即時反映にしたい場合は、あいだに中継役（Cloudflare Workers など）を1つ挟めば
実現できます。ただし次の点を承知したうえで判断してください。

- 中継役のサービスを1つ増やすことになる（障害点が増える）
- GitHubのトークンを中継役に置くことになり、**有効期限が切れると静かに止まる**
- 得られるのは「最大15分 → 1〜2分」の短縮だけ

**部品を増やさないほうが長く運用できる**と考え、標準では15分おきの確認にしています。
必要になったときのため、ワークフロー側には受け口（`repository_dispatch`）だけ
残してあります。

### 頻度を変えたい場合

`.github/workflows/sync-cms.yml` の `cron` を書き換えてください。

```yaml
- cron: '*/15 * * * *'   # 15分おき（現在の設定）
- cron: '*/30 * * * *'   # 30分おき
- cron: '0 * * * *'      # 1時間おき
- cron: '0 23 * * *'     # 毎朝8時（日本時間）だけ
```

このリポジトリは公開設定のため、**GitHub Actions の実行時間は無料・無制限**です。
頻度を上げても料金はかかりません。

## ⑤ 既存53件のデータを移す

現在のデータは `data/properties.csv` にあります。microCMS には **CSVインポート機能はありません**
（2026年8月時点）。移しかたは2通りです。

**A. 管理画面から手で入れる（おすすめ）**

53件は多く感じますが、**移行は入力ルールを覚える最良の機会**です。
また現在のデータはサンプルなので、**実際の物件だけを入れれば十分**なはずです。

**B. CSVから一括登録する（件数が多いとき）**

管理画面のCSV取り込みでは「交通」（繰り返しフィールド）を登録できないため、
APIから登録する仕組みを用意してあります。**パソコンに何も入れずに、
GitHubの画面だけで実行できます。**

1. 登録したいCSVを `data/import/` に置く
   （**Add file → Upload files** でドラッグ＆ドロップ）
2. microCMS の **サービス設定 → APIキー** で、`PUT` にチェックを足す
   （無料プランはキーを1つしか作れないため、既存のキーに一時的に足します。
   `GET` は外さないでください）
3. GitHub の **Settings → Secrets and variables → Actions** で
   `MICROCMS_WRITE_API_KEY` にそのキーを登録
4. **Actions タブ →「物件をCSVから一括登録」→ Run workflow**
   - 最初は **「確認だけ（何も登録しません）」** で実行し、内容を確認
   - 問題なければ「公開状態で登録」または「下書きとして登録」で再実行
5. **終わったら Secrets のキーを削除し、`PUT` の権限も外してください**

> 物件番号がコンテンツIDになるため、**同じCSVを再実行しても重複しません**（上書き）。
> 送信前に全件を検証し、**エラーが1件でもあれば何も送りません。**

交通は `JR山手線・埼京線「大崎」駅徒歩4分／都営浅草線「五反田」駅徒歩6分`
のような文章から、路線・駅・徒歩分に自動で分解されます。

## ⑥ 動作を確認して、スプレッドシート運用を止める

1. microCMS に物件を1件入れて「公開」する
2. GitHub の **Actions** タブに「物件情報を反映（microCMS）」が現れ、
   緑のチェック ✅ が付くことを確認する
3. サイトにその物件が出ることを確認する
4. **わざと間違えた入力**（存在しないエリア名など）で公開し、
   Actions が赤い ✕ になり、**サイトが変わらないこと**を確認する
   → これが確認できれば、以後は安心して運用できます

確認できたら、次の後片付けをしてください。

- [ ] スプレッドシートを「保管用」にする（編集権限を外す）
- [ ] `.github/workflows/sync-sheet.yml` を削除する
- [ ] `tools/sheet-url.txt` `tools/sheet-notice.md` `tools/lib/sheet.js` を削除する
- [ ] `tools/fetch-sheet.js` を削除する
- [ ] `tools/lib/drive.js` `tools/drive-folder-id.txt` `tests/drive.js` を削除する
      （写真もmicroCMSに入るため、ドライブ連携は不要になります）
- [ ] README.md と MANUAL.md から、スプレッドシートの記述を削除する

> **この後片付けは、microCMSでの運用が1〜2週間問題なく回ってから**行ってください。
> それまでは、Actionsタブから「【予備】スプレッドシートを反映」を手動実行すれば
> 元の運用に戻せます。

## 動作の確認（設定後、手元で試す場合）

```bash
export MICROCMS_API_KEY=＜APIキー＞
node tools/fetch-cms.js --check   # 取得して検証するだけ（何も書き換えません）
node tools/fetch-cms.js           # 取り込んでサイトのデータまで作る
```

`--check` は**書き込みを一切行いません**。設定が合っているかの確認に使ってください。

## 困ったとき

| 症状 | 原因と対処 |
|---|---|
| `MICROCMS_API_KEY が設定されていません` | Secrets の名前が違うか、未登録です |
| `microCMS の認証に失敗しました（HTTP 401）` | APIキーの値が違うか、GET権限がありません |
| `microCMS のAPIが見つかりません（HTTP 404）` | `serviceDomain` か エンドポイント名（`properties`）が違います |
| 「公開」したのにサイトに出ない | 最大15分かかります。急ぐときは Actions の Run workflow を押してください |
| 特定の物件だけ反映されない | Actions のログを見てください。どの物件の何が問題かが日本語で出ます |
